HOTFIX183 / Phase 4P.9CK — Viewport-Scoped PDF Page Prioritization, Progressive Resolution Upgrade, and Scroll-Stability Parity

Summary
- Introduced LOW/HIGH PDF thumbnail render tiers in AsyncThumbnailService.
- Visible PDF requests now favor a lower-cost first-pass render and record a viewport-scoped promotion intent.
- After the viewport settles, the current visible PDF set is eligible for HIGH-tier promotion.
- Promotion requests are discarded when viewport scope advances or the file version changes.
- Low-tier PDF results remain memory-scoped; HIGH-tier results replace cache truth and persist to disk cache.
- Added per-document PDF fairness counters/guards to reduce monopolization by repeated promotion work.

Primary implementation surface
- src/main/java/com/fileexplorer/service/icon/AsyncThumbnailService.java

Notes
- The current Explorer pipeline still renders page 0 for file thumbnails, but the new PdfRenderKey / PdfViewportState scaffolding is structured so later work can extend prioritization semantics without reworking the entire PDF request path.
- This hotfix is intentionally conservative about promotion concurrency so visible-first behavior wins over background quality upgrades.
