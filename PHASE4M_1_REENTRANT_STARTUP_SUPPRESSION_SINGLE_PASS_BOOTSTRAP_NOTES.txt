HOTFIX32 / Phase 4M.1 — Reentrant Startup Suppression and Single-Pass Bootstrap

What changed
- added a stage-scoped bootstrap state machine in MainApp (NOT_STARTED, SHELL_VISIBLE, MAIN_FXML_LOADED, MAIN_UI_ATTACHED, STARTUP_COMPLETE, FAILED, DISPOSED)
- added bootstrap claim/suppression guards so the same Stage cannot re-enter configureExplorerStage after startup begins
- added request logging with explicit bootstrap reason, target folder, and first external caller summary
- split bootstrap entry points so secondary windows must use an explicit reason string
- suppressed duplicate initial-folder bootstrap opens per Stage
- removed the redundant stage.show() call from MainController.openNewWindow because configureExplorerStage already shows the Stage
- updated breadcrumb/new-window call sites to use explicit secondary-bootstrap reasons

Why
- the startup log showed a second full bootstrap sequence long after initial startup
- this pass hardens the lifecycle so normal cold startup stays single-pass and accidental re-entry is visible in the trace if another caller tries to bootstrap again

Expected result
- one primary bootstrap per normal app launch
- no duplicate initial-directory bootstrap on the same window
- any later configureExplorerStage attempts now log their reason/caller and are suppressed unless they are explicit secondary-window requests
