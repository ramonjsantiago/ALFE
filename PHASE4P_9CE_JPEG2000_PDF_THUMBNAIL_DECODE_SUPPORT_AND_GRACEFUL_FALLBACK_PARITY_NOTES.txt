HOTFIX177 / Phase 4P.9CE — JPEG2000 PDF Thumbnail Decode Support and Graceful Fallback Parity

Summary
- Adds explicit Maven runtime support for JPX/JPEG2000 decoding via jai-imageio-jpeg2000.
- Prevents repeated noisy PDF thumbnail failures when a PDF contains JPX streams but the JPEG2000 reader is not present at runtime.
- Preserves normal thumbnails4j/PDFBox thumbnail rendering for standard PDFs.

Changed Files
- pom.xml
- src/main/java/com/fileexplorer/service/icon/AsyncThumbnailService.java

Implementation Notes
1. pom.xml
   - Added com.github.jai-imageio:jai-imageio-jpeg2000:${jai.imageio.version}.

2. AsyncThumbnailService
   - Retains ImageIO.scanForPlugins() and now immediately primes a JPEG2000 reader availability probe.
   - Adds a bounded ASCII token scan for /JPXDecode and related JPX markers before invoking PDF thumbnail rendering when the JPEG2000 reader is absent.
   - Falls back cleanly to the existing non-thumbnail path when JPX is detected without a decoder.
   - Emits a one-shot warning instead of repeated stack traces for the same missing runtime capability.

Expected Result
- After a clean Maven refresh/rebuild, PDFs with JPEG2000/JPX image streams should thumbnail correctly when the codec is present.
- If the codec is still unavailable at runtime for any reason, the app should avoid repeated noisy JPX thumbnail failures and continue showing the normal PDF/file icon fallback.
