HOTFIX164 / Phase 4P.9BR — Inline Rename Validation, Extension Editing Rules, and Commit/Error UX Parity

Summary
- Hardened inline rename validation so blank names, reserved Windows device names, illegal characters, and trailing dots/spaces are rejected without dropping the rename session.
- Preserved the user’s typed draft during invalid commits and immediately restored focus to the active inline-rename surface in Details and icon-based views.
- Added basename-vs-full-name edit tracking so file renames still preserve extensions during normal basename edits while allowing explicit whole-name replacement when the user edits the full text.

Implementation notes
- MainController now keeps a pending inline-rename draft buffer and a select-all retry mode for invalid commit retries.
- Inline rename fields in both Details cells and icon/list/tile/content surfaces now restore the draft text and focus state after validation failures.
- Validation now blocks blank or whitespace-only names, reserved Windows device names (CON/PRN/AUX/NUL/COMx/LPTx), illegal filename characters, and trailing spaces/dots.
- Successful commits clear the draft buffer and keep the existing selection/refresh pipeline intact.
