HOTFIX166 / Phase 4P.9BT — Create/Rename Focus-Restore, Escape/Revert Semantics, and Post-Commit Selection Parity

Summary
- Added a shared inline rename/create session model that snapshots selection, focus, anchor, and active surface before edit starts, then restores or finalizes that state after cancel, failure, or commit.
- Implemented Explorer-style Escape handling for transient newly created items so cancelling a queued inline rename removes the empty created item and restores the previous selection/focus context.
- Added post-commit focus guards and completion/failure handling so rename/create flows keep the committed item selected and visible, while failed commits reopen inline rename with the draft text preserved.

Primary implementation notes
- MainController now tracks pending created-item rename sessions separately from active rename sessions so create flows preserve the pre-create selection/focus snapshot instead of capturing the transient item as the baseline.
- MainController.commitInlineRename(Path, String) now carries commit state through operation completion, reopens rename on validation/operation failure, and finalizes post-commit selection/focus once the refreshed listing contains the committed path.
- MainController.applyDirectoryListing(Path, List<FileItem>) now detects waiting rename/create sessions after refresh, finalizes committed-path selection once the target appears, and restores cancelled-create focus/selection snapshots after the deleted transient item drops out of the listing.
- MainController’s tree edit-cancel wiring now routes Escape cancellation through the same session restore path while suppressing recursive cancel events during controller-driven editor teardown.
