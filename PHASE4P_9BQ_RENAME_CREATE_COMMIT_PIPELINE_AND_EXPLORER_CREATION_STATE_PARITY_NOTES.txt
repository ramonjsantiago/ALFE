HOTFIX163 / Phase 4P.9BQ — Rename/Create Commit Pipeline and Explorer Creation-State Parity

Scope delivered in this phase
- New Folder and New Text Document creation now re-enter inline rename through the currently active surface instead of assuming Details view only.
- Icon-based views (Extra large, Large, Medium, Small, List, Tiles, Content) now render an inline TextField on the created or renamed item and keep that item selected/focused through create, cancel, and retry paths.
- Inline rename now rejects invalid names and duplicate targets before execution, and no longer overwrites an existing item during rename fallback execution.
- File inline rename selects only the basename when an extension is present, and commits without an explicit extension preserve the original extension.

Implementation notes
- MainController now scrolls/focuses the active icon surface back to the rename target after create/cancel/retry.
- Icon-tile builders switch the tile label region into an inline rename field when the shared inlineRenameTablePath matches the tile path.
- The create pipeline still uses the shared TableView selection model as the source of truth, but presentation is now view-aware.
