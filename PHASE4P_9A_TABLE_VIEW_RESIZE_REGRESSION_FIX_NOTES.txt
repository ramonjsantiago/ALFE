HOTFIX94 / Phase 4P.9A — Table View Resize Regression Fix

Summary
- Corrects the HOTFIX93 regression that pinned Table View sizing during later application-window resizes.
- Preserves the responsive relayout trigger path, but stops forcing pref widths onto the table/details shell.

Implementation
- The responsive Table View refresh now uses layout/policy reapplication instead of writing a fixed pref width.
- `detailsViewShell` and `fileTable` are reset to `Region.USE_COMPUTED_SIZE` before constrained relayout.
- Added a width-change guard so repeated self-triggered layout churn does not keep reapplying the same size.

Expected result
- Table View resizes again with the application window.
- The Details/Table shell is no longer pinned to a stale width set by HOTFIX93.
- The flex-last-column constrained resize policy is still re-applied during responsive relayout.
