HOTFIX175 / Phase 4P.9CC — Velocity-Aware Prefetch Windows, Decode Cancellation, and Viewport Settle Parity

Summary
- Added velocity-aware prefetch windows so viewport look-ahead grows during fast scroll bursts and relaxes again once motion settles.
- Added viewport-scope cancellation semantics to async icon and thumbnail pipelines so stale viewport work is pruned sooner and stale completions are discarded instead of repainting after the user has already outrun them.
- Added a post-idle viewport settle pass that reasserts selection/focus continuity and performs one direct visible-first realization refresh after the viewport stops moving.

Implementation details
- MainController
  - Tracks smoothed scroll velocity in px/ms and classifies motion into settle/slow/medium/fast/fling buckets.
  - Adapts Details and icon-view prefetch windows using direction-aware leading/trailing multipliers.
  - Logs realization telemetry with visible count, prefetched count, velocity bucket, and current view when telemetry flags are enabled.
  - Schedules a dedicated viewport settle pass after scroll idle to normalize selection/focus continuity and issue one direct visible-first refresh.
- AsyncThumbnailService
  - Added viewport-scope generations for non-user-action work.
  - Pending/queued stale viewport work is pruned when motion advances the viewport scope.
  - Stale viewport completions are discarded before caching/apply, with dedicated diagnostics counters.
- AsyncIconService
  - Added the same viewport-scope generation, pending/queue pruning, and stale-completion discard behavior for icon work.

Suggested diagnostics flags
- -Dfileexplorer.scroll.telemetry=true
- -Dfileexplorer.realization.telemetry=true
- -Dfileexplorer.debug.icons=true
- -Dfileexplorer.debug.thumbs=true

Acceptance intent
- Fast scrolling widens look-ahead without letting stale off-screen decode work pile up.
- When the viewport changes, stale prefetch/background work is pruned earlier and stale completions do not repaint recycled cells.
- When scrolling stops, one settle pass reasserts selection/focus continuity and fills the final visible set cleanly.
