HOTFIX168 / Phase 4P.9BV — Directory-Watcher Refresh Coalescing, Self-Event Deduplication, and Selection Persistence Parity

Summary
- Added a short-lived self-originated refresh stabilization window around local create/rename flows so immediate watcher-style rebinds for the same directory are treated as part of one logical commit.
- Coalesced same-directory refresh requests during that stabilization window to reduce bursty reload chains that can otherwise cause double-scroll, double-reveal, and transient selection churn right after commit.
- Suppressed duplicate refreshed listings for the same locally edited directory when the listing signature has not changed, preserving the already-restored selection, lead/focus path, and viewport instead of repainting the same post-commit state again.

Primary implementation notes
- MainController now starts a self-refresh stabilization scope for locally created folders, inline rename commits, and transient create-cancel cleanup refreshes.
- MainController.refresh() now routes same-directory post-edit refreshes through a short FX-thread debounce while stabilization is active, which collapses repeated self-event refresh requests into one load pass.
- MainController.applyDirectoryListing(Path, List<FileItem>) now computes a lightweight order-independent listing signature and ignores duplicate post-edit listings for the stabilized directory.
- Failure and cancel paths now clear the stabilization state so invalid rename attempts do not leave later unrelated refreshes coalesced or deduplicated by accident.
