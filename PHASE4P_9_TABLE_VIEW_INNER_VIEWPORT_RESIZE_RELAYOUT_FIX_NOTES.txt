HOTFIX93 / Phase 4P.9 — Table View Inner Viewport Resize Relayout Fix

Goal
- keep Details/Table view responsive to the live inner viewport width during repeated application-window resize cycles
- let the table fill the remaining center content width when the right Details/Preview side pane is hidden
- avoid stale constrained-column layout after navigation-pane and split-pane changes

What changed
- MainController now installs a dedicated responsive table-viewport refresh path with a debounced relayout pass
- table responsive listeners now react to fileTable, detailsViewShell, viewHost, contentSplitPane, sidePane, Scene, and Window size/visibility changes
- the responsive table pass snaps the table and its shell to the currently visible inner width, requests a layout pass, and reapplies the flex-last-column constrained resize policy on the next pulse
- split-pane and navigation-pane visibility changes now also schedule responsive table and icon viewport refreshes after divider positions are updated
- switching back into Details view schedules a live table viewport relayout so the table reopens at the current center width

Expected result
- Table View should keep tracking the actual visible center width across later stretch/shrink cycles instead of reverting to a stale fixed width
- when the right Details/Preview pane is hidden, the table should grow to occupy the remaining center content area
- header/content alignment should remain more stable because constrained-column layout is retriggered after split changes and window resize churn
