Phase 4O.7 reintroduces persistent thumbnail caching carefully and fail-open.

Scope
- read-through / write-through disk cache for successful thumbnail renders
- keyed by path + extension + size bucket + last modified + file size + provider
- scoped to document thumbnails by default to avoid disturbing the faster native/imageio paths
- cache reads/writes are best effort only; any failure falls back to the existing live thumbnail pipeline and then to the normal file-type icon
- periodic age/size pruning keeps the cache bounded

Tuning
- -Dfileexplorer.thumb.diskCache.enabled=true|false
- -Dfileexplorer.thumb.diskCache.documentsOnly=true|false
- -Dfileexplorer.thumb.diskCache.maxBytes=<bytes>
- -Dfileexplorer.thumb.diskCache.maxAgeDays=<days>
- -Dfileexplorer.thumb.diskCache.pruneEveryWrites=<count>
- -Dfileexplorer.thumb.diskCache.dir=<path>
