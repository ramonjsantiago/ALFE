HOTFIX182 / Phase 4P.9CJ — Adaptive PDF Render Budgeting, First-Page Heuristics, and Large-Document Recovery Parity

Scope
- replace the fixed PDF thumbnail timeout posture with adaptive budgeting informed by file size and recent render history
- bias PDF first-page thumbnails toward faster readiness for very large, very long, or recently slow documents
- avoid repeated expensive retries for pathological large PDFs while still allowing retry-after-change recovery

Implementation summary
1. AsyncThumbnailService
   - added adaptive PDF timeout budgeting via `timeoutBudgetMsFor(...)` and `computeAdaptivePdfTimeoutMs(...)`
   - added per-file-identity PDF render history snapshots for recent average render latency and timeout streak tracking
   - added first-page planning via `buildPdfRenderPlan(...)`, `computeAdaptivePdfTargetSizePx(...)`, and `computeAdaptivePdfScaleCap(...)`
   - added worker-side PDF budget checks so long-running PDF work can self-abort to a quiet fallback before the outer timeout path has to intervene
   - added large-document recovery fallback when PDFs exceed the hard large-document threshold or hit repeated timeout streaks while already above the soft threshold
   - preserved H181 file-identity invalidation so changing the PDF clears adaptive history/recovery state automatically
   - extended thumbnail diagnostics and the disk-cache manifest fingerprint with the new adaptive PDF planning knobs

2. Tests
   - added `AsyncThumbnailServiceHotfix182Test`
   - verifies adaptive timeout growth for large/slower PDFs
   - verifies heuristic thumbnail-size downshift for large/slow first-page cases
   - verifies large-document recovery state resets after the PDF changes

Expected outcome
- PDFs that are merely slow should get a more reasonable budget before being treated as a failure
- visibly expensive PDFs should downshift earlier to a cheaper first-page thumbnail plan instead of always using the full requested render posture
- pathological large PDFs should stop thrashing the PDF lane and should recover automatically after the file changes
