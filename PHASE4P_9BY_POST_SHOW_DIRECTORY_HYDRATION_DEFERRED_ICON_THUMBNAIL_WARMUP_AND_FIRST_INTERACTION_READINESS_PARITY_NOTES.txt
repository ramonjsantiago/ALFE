HOTFIX171 / Phase 4P.9BY — Post-Show Directory Hydration, Deferred Icon/Thumbnail Warmup, and First-Interaction Readiness Parity

Summary
- Keeps shell-first startup focused on first paint and defers the initial directory hydration into a post-show handoff.
- Opens the async icon upgrade gate only after the first visible directory batch is committed.
- Opens the thumbnail warmup gate only after first-interaction readiness, with a fallback timer so startup does not stall forever if the user does nothing.
- Uses a smaller startup first batch plus a bounded startup batch size for progressive directory enumeration.

Implementation notes
- `MainApp.configureExplorerStage(...)` now schedules `MainController.beginPostShowHydration(...)` on the startup critical queue instead of opening the initial folder immediately.
- `MainController.beginPostShowHydration(...)` adds explicit startup trace milestones and arms first-interaction tracking.
- `MainController.loadDirectoryIntoTableAsync(...)` now passes both a startup first-batch size and a normal follow-on batch size into `DirectoryLoadManager.loadProgressive(...)`.
- `DirectoryListingService.listProgressiveSync(...)` now emits a smaller first batch before switching to the steady-state batch size.
- `AsyncIconService` now waits behind an enablement gate so placeholder icons remain cheap during the shell-to-content handoff.
- Current-folder thumbnail warmup is blocked until the thumbnail warmup gate is explicitly opened.

Operational limitations in this packaging
- Source changes are included for the full project tree, but this environment does not provide Maven/JavaFX build verification, so `target/` artifacts were not regenerated here.
